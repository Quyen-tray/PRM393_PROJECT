## Chênh lệch tài liệu và các guard không được bỏ qua

1. API Reference không liệt kê quiz question/answer APIs, admin question replacement, completion review, employee document catalog, employee violations/explanations.
2. Flutter case1 đã sửa authMe sang /api/v1/users/me; sai lệch /auth/me chỉ còn ở snapshot case2 cũ.
3. Device review có STAFF_REVIEW service guard ngoài DEVICE_APPROVE controller guard.
4. Khi cùng dùng PreAuthorize, annotation ở method thay thế annotation ở class; không tự AND hai biểu thức. Service checks vẫn áp dụng thêm. Vì vậy phải phân biệt guard của action payroll với quyền đọc danh sách/readiness để hoàn tất UI flow. Xem [Spring Security Method Security](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html).
5. Check-in training eligibility được gọi nhưng TrainingService hiện trả eligible=true; requirements là dữ liệu hiển thị, không chặn ca tại source case1.
6. API Reference và source đều chưa được đối chiếu qua live /v3/api-docs.
7. SQL table names ở đây lấy từ entity và config.sql case1, không phải logical table names của SRS.
8. Test source chưa chạy; không suy coverage hoặc pass từ tên file. Các repo dùng nhiều Map và một số method bỏ page metadata nên count/drill-down cần review theo [BUSINESS_LINKAGE_MATRIX.md](BUSINESS_LINKAGE_MATRIX.md).
9. Device approval hiện kiểm tra deviceId/owner/status; Flutter chọn ACTIVE record đầu tiên, chưa đối chiếu thiết bị hiện tại. Đây là gap binding cần chốt.
10. Workspace/route guard chưa tập trung; approval hub Future.wait nhiều API có thể lỗi toàn hub khi một nguồn 403. Không suy quyền thao tác từ việc route đã render.
